Chapter 11

Project: An Expense Tracker

The last ten chapters each introduced one idea at a time: values, expressions, decisions, loops, functions, recursion, arrays and maps. This chapter builds one complete program, an expense tracker, from start to finish, and uses nearly everything you have learned along the way.

Also, we introduce two new ideas here. The first is reading and writing files. The tracker keeps its data in a file, so your expenses will survive a program restart. The second idea is type coercion or type conversion. Each expense is stored in a map whose values have different types. Getting a typed value back out of such a map needs a new expression, convert.

The Project

Here is what the finished tracker will do. You start it from the command line, and it waits for commands:

$ nex tracker.nex
8 expenses loaded
> months
2026-10  961.15
2026-11  341.75
> budget
month (YYYY-MM): 2026-11
Food: 112.45 of 120.00  close
Housing: 204.30 of 1000.00  ok
Transport: 25.00 of 20.00  OVER
> quit

It can list every expense, total them by month, print a report broken down by category and subcategory, compare a month's spending against a budget, and record new expenses. Every new expense is written to a file straight away, so the next run starts with everything recorded so far.

We build the tracker one function at a time in the REPL, testing each piece as we go. Section 11.13 puts the pieces together into a program file.

Designing the Log File

Before writing any code, decide how the data will be stored. Each expense has three facts: the date it happened, what it was for, and how much it cost. We store one expense per line of a plain text file called expenses.txt, with the three facts separated by commas:

2026-10-28,Housing/Rent,900.00
2026-10-30,Food/Groceries,61.15
2026-11-01,Housing/Utilities,84.30
2026-11-02,Food/Groceries,42.50
2026-11-03,Food/Dining out,31.20
2026-11-04,Food/Groceries,12,40
2026-11-05,Transport,25.00
2026-11-08,Food/Groceries,38.75
2026-11-09,Housing/Repairs/Plumbing,120.00

A few decisions are packed into this format:

  • Plain text. You can read the file, and fix a mistake in it, with any text editor. Nothing about it is specific to Nex.
  • One line per expense. Recording a new expense means adding one line at the end. The lines that are already there never need to change.
  • Dates as YYYY-MM-DD. Written this way, dates sort correctly as plain strings, and every date in November 2026 starts with 2026-11.
  • Categories as paths. Food/Groceries means "Groceries, which is part of Food". A category can go as deep as it needs to: Housing/Repairs/Plumbing. This is what will let us total spending at every level later on.

Look closely at the sixth line. Someone typed 12,40, using a comma as the decimal point, so the line now has four fields instead of three. Files that people edit by hand contain mistakes like this, and the tracker must not trip over them. We will come back to this line in Section 11.4.

Reading and Writing Files

The finished tracker will run as a program file, and Nex always checks the types in a program file before running it. So let the REPL check types too, as we did in Section 6.6, and every piece we write will be checked as we go:

nex> :typecheck on
Type checking enabled. Code will be validated before execution.

Nex works with files through Path, a type from its standard library that stands for a file or folder. You saw it briefly in the word counter of Chapter 1. A library type has to be brought in with intern before you can use it:

nex> intern io/Path
nex> let notes: Path := create Path.make("notes.txt")
notes.txt
nex> notes.exists
false

create Path.make("notes.txt") makes a Path object for the file name you give it. A relative name like this one is looked up in the folder Nex was started from. Making a Path does not touch the disk, so it is fine that the file does not exist yet: exists says so. (Path is a class, and create is how you make an object of a class. You have used create before, for Map.from_entries in Chapter 10. Chapter 12 shows how classes like this are written.)

Three methods do almost all the work:

  • write_text(text) replaces the whole file with text, creating it if necessary.
  • append_text(text) adds text to the end of the file, creating it if necessary.
  • read_text returns the whole file as one String.
nex> notes.write_text("milk\n")
nex> notes.append_text("bread\n")
nex> notes.read_text
"milk
bread
"
nex> notes.exists
true

"\n" is the newline character. Files do not end lines by themselves, so each line we write must end with one. To work with a file line by line, read it and split the text at the newlines:

nex> notes.read_text.split("\n")
["milk", "bread"]

Notice that the newline at the very end does not produce an empty last line. split drops it for us.

The difference between write_text and append_text matters for the tracker. Recording an expense only needs append_text: the new line goes at the end and nothing else is touched. Changing or deleting an expense would need write_text, because the whole file has to be written out again. Exercise 2 asks you to do exactly that.

Now point a Path at the real log. With expenses.txt from Section 11.2 saved in the folder you started Nex from:

nex> let file: Path := create Path.make("expenses.txt")
expenses.txt
nex> file.read_text.split("\n").length
9

Next we turn the nine lines into expenses.

Parsing a Line

Turning text into data is called parsing. A line of the log is easy to take apart: split it at the commas.

nex> let fields := "2026-11-02,Food/Groceries,42.50".split(",")
["2026-11-02", "Food/Groceries", "42.50"]
nex> fields.get(2)
"42.50"
nex> fields.get(2).to_real
42.5

The amount arrives as a String, and to_real converts it into a number. Before we store amounts as Reals, though, look at this:

nex> 0.1 + 0.2
0.30000000000000004

A Real stores a number in binary, and most decimal fractions, like 0.1, have no exact binary form. The error is tiny, but it shows up as soon as you add many amounts together and print the total. Money has to add up exactly. The usual remedy is to count money in its smallest unit: store 42.50 as 4250 cents, an Integer, and add integers, which are always exact.

nex> (42.50 * 100.0).round
4250

There is a catch. to_real raises an error if the text is not a number, and one bad line should not stop the program. So check the text first. A valid amount is non-empty, made only of digits and dots, and has at most one dot:

nex> function is_amount(text: String): Boolean
     do
       result := text.length > 0
         and text.all(fn (c) => "0123456789.".contains(c.to_string))
         and text.count(fn (c) => c = #.) <= 1
     end
nex> is_amount("42.50")
true
nex> is_amount("4x.50")
false
nex> is_amount("1.2.3")
false

A string is a sequence of characters, and like an array it has all and count (Section 9.9). Here they visit each character c in turn. #. is the character literal for a dot.

Now the whole line. parse_line checks each part and returns the expense if everything is in order, or nil if anything is wrong. Its return type is detachable, ?Map[String, Any], because "no expense on this line" is a normal outcome, not an error (Section 2.10).

nex> function parse_line(line: String): ?Map[String, Any]
     do
       result := nil
       let fields := line.split(",")
       if fields.length = 3 then
         let date := fields.get(0).trim
         let category := fields.get(1).trim
         let amount := fields.get(2).trim
         if date.length = 10 and category.length > 0 and is_amount(amount) then
           result := {"date": date, "category": category,
                      "cents": (amount.to_real * 100.0).round}
         end
       end
     end
nex> parse_line("2026-11-02,Food/Groceries,42.50")
{"date": "2026-11-02", "category": "Food/Groceries", "cents": 4250}
nex> parse_line("2026-11-04,Food/Groceries,12,40") = nil
true

The line with 12,40 has four fields, so parse_line turns it down. The checks are deliberately simple: a date is anything ten characters long, for instance. They catch the common mistakes without making the function hard to read.

An expense comes back as a map with three entries: two strings and an integer. Because the values have different types, the map's value type has to be Any. We will see what that costs us in Section 11.6.

An Array of Records

Each expense is a small record: a few named fields that belong together. A whole log is a sequence of them, so it is an array of maps, Array[Map[String, Any]]. Loading the log means reading the file, parsing every line, and keeping the expenses that parse:

nex> function load_expenses(file: Path): Array[Map[String, Any]]
     do
       result := []
       if file.exists then
         across file.read_text.split("\n") as line do
           if ? parse_line(line) as expense then
             result.add(expense)
           end
         end
       end
     end
nex> let expenses := load_expenses(file)
nex> expenses.length
8

Of the nine lines in the file only eight were turned into expenses: the line with 12,40 was skipped. Two details are worth noticing. If the file does not exist yet, which is true the first time anyone runs the tracker, load_expenses returns an empty array instead of failing. And if ? parse_line(line) as expense then is the binding form from Section 2.10: inside the then branch, expense is the parsed map and is known not to be nil.

Reading a field takes two steps: pick the record from the array by position, then the value from the record by key.

nex> expenses.get(3)
{"date": "2026-11-02", "category": "Food/Groceries", "cents": 4250}
nex> expenses.get(3).get("category")
"Food/Groceries"

The chain expenses.get(3).get("category") reads as "the category of the expense at index 3", which is the fourth expense, since indexes count from zero (Section 9.2).

The convert Expression

Now try to use an amount:

nex> let first := expenses.get(0)
{"date": "2026-10-28", "category": "Housing/Rent", "cents": 90000}
nex> first.get("cents") + 1
Type error at line 1, column 1: Operator + requires numeric or String operands, got Any and Integer
Error: Type checking failed
nex> let c: Integer := first.get("cents")
Type error at line 1, column 1: Cannot assign Any to variable 'c' of type Integer without narrowing it first. Use `convert ... to <name>: Integer then ... end`.
Error: Type checking failed

We know the value is 90000, but Nex does not. The record is a Map[String, Any], so as far as the type checker can tell, get could return anything at all: a string, a number, an array. With type checking on, the REPL shows this by printing each result's type in front of it. For expenses.get(3).get("category") it prints Any "Food/Groceries". You cannot add one to anything, so Nex refuses.

The error message names the way out. The convert expression checks, while the program runs, whether a value really has the type you expect:

if convert expr to name: Type then
   -- use name here
end

If the value of expr is a Type, the conversion succeeds, and inside the then branch name holds the value with that type. If it is not, the conversion fails and the else branch, if there is one, runs instead:

nex> if convert first.get("cents") to cents: Integer then
       print(cents + 1)
     end
90001
nex> if convert first.get("date") to n: Integer then
       print("a number")
     else
       print("not an Integer")
     end
"not an Integer"

Writing a convert every time we read a field would bury the interesting code. So we do what Chapter 7 recommends and hide the detail inside small functions, one for each kind of field:

nex> function text_of(record: Map[String, Any], key: String): String
     do
       result := ""
       if convert record.get(key) to text: String then
         result := text
       end
     end
nex> function cents_of(record: Map[String, Any]): Integer
     do
       result := 0
       if convert record.get("cents") to cents: Integer then
         result := cents
       end
     end
nex> text_of(first, "category")
"Housing/Rent"
nex> cents_of(first)
90000

If a field is missing or holds the wrong type, these functions return a harmless default: an empty string or zero. That suits the tracker, because every record comes from parse_line, which always fills in all three fields with the right types. The conversions will always succeed. They are there because the type checker cannot know that, and convert is how we tell it what we know.

One more helper turns cents back into the familiar form for printing:

nex> function format_cents(cents: Integer): String
     do
       let rest := cents % 100
       result := (cents / 100).to_string + "." + when rest < 10 then "0" else "" end + rest.to_string
     end
nex> format_cents(cents_of(first))
"900.00"
nex> format_cents(5)
"0.05"

Dividing two integers gives an integer, so cents / 100 is the whole part and cents % 100 is what is left over. The when expression adds a leading zero when there are fewer than ten cents, so that five cents prints as 0.05, not 0.5.

Asking Questions

With the expenses loaded and the accessors written, questions about our spending become short functions. The total of a list of expenses is a fold (Section 9.9):

nex> function total(expenses: Array[Map[String, Any]]): Integer
     do
       result := expenses.fold(0, fn (sum, e) => sum + cents_of(e))
     end
nex> format_cents(total(expenses))
"1302.90"

The expenses for one month are a filter: an expense belongs to November 2026 exactly when its date starts with 2026-11.

nex> function in_month(expenses: Array[Map[String, Any]], month: String): Array[Map[String, Any]]
     do
       result := expenses.filter(fn (e) => text_of(e, "date").starts_with(month))
     end
nex> let november := in_month(expenses, "2026-11")
nex> november.length
6
nex> format_cents(total(november))
"341.75"

Both functions are pure (Section 7.2): they compute an answer from their arguments and change nothing. That is why they combine so easily: total(in_month(expenses, "2026-11")) is the November total.

How much went on each top-level category? First, a function to pick the top level out of a category path:

nex> function top_level(category: String): String
     do
       result := category.split("/").get(0)
     end
nex> top_level("Housing/Repairs/Plumbing")
"Housing"

Then the counting pattern from the word-frequency counter of Chapter 10, adding up cents instead of counting words:

nex> function totals_by_category(expenses: Array[Map[String, Any]]): Map[String, Integer]
     do
       result := {}
       across expenses as e do
         let name := top_level(text_of(e, "category"))
         result.set(name, result.try_get(name, 0) + cents_of(e))
       end
     end
nex> let totals := totals_by_category(november)
{"Housing": 20430, "Food": 11245, "Transport": 2500}
nex> across totals.keys.sort as name do
       console.print_line(name + ": " + format_cents(totals.get(name)))
     end
Food: 112.45
Housing: 204.30
Transport: 25.00

The report uses console.print_line rather than print, because print would put quotes around each line. Sorting the keys first gives the categories in alphabetical order rather than the order they were first seen.

Finally, what share of the month went where? This is a job for the map functions of Section 10.8. map turns each entry into a new entry holding a percentage, and Map.from_entries collects the entries into a map:

nex> let grand := total(november)
34175
nex> create Map.from_entries(totals.map(fn (e) => create Map_Entry.make(e.key, e.value * 100 / grand)))
{"Housing": 59, "Food": 32, "Transport": 7}

Integer division rounds each share down, which is why the shares add up to 98 rather than 100.

Grouping by Month

An array of maps keeps records in sequence. The opposite shape, a map of arrays, is the natural way to group records under a name. Grouping the expenses by month gives a map from each month to the array of that month's expenses, Map[String, Array[Map[String, Any]]]:

nex> function by_month(expenses: Array[Map[String, Any]]): Map[String, Array[Map[String, Any]]]
     do
       result := {}
       across expenses as e do
         let month := text_of(e, "date").substring(0, 7)
         let group := result.try_get(month, [])
         group.add(e)
         result.set(month, group)
       end
     end
nex> let months := by_month(expenses)
nex> months.keys
["2026-10", "2026-11"]
nex> months.get("2026-10").length
2

The body of the loop is the standard way to build up a nested structure one item at a time: get the inner array (or an empty one if this month has not appeared yet), modify it, and set it back. Setting it back is what stores a brand-new array in the map. For a month already in the map, group is the very array stored there, so add changes it in place and set just stores it again.

With the groups built, a monthly summary is a loop over the months:

nex> across months.keys as month do
       console.print_line(month + ": " + format_cents(total(months.get(month))))
     end
2026-10: 961.15
2026-11: 341.75

Notice how much of this is reuse. total was written for "all expenses", but it works on any array of expenses, including one month's group. Small functions with clear jobs keep paying off.

A Tree of Categories

Top-level totals hide the detail: was it groceries or eating out that made Food so expensive? The category paths say how the categories nest. Food contains Groceries and Dining out. Housing contains Rent, Utilities and Repairs, and Repairs contains Plumbing. Drawn out, the categories form a tree:

All
├── Housing
│   ├── Rent
│   ├── Utilities
│   └── Repairs
│       └── Plumbing
├── Food
│   ├── Groceries
│   └── Dining out
└── Transport

Each box in the tree is a node. Each node has a name, the amount recorded directly against it, and any number of child nodes, each of the same kind. Nex has no built-in tree type, so we build one from what we have: a node is a map with a "name", its own "cents", and a "children" array holding the child nodes. The three values have three different types, so this is another Map[String, Any], and reading it needs convert again:

nex> function new_node(name: String): Map[String, Any]
     do
       result := {"name": name, "cents": 0, "children": []}
     end
nex> function children_of(node: Map[String, Any]): Array[Map[String, Any]]
     do
       result := []
       if convert node.get("children") to children: Array[Map[String, Any]] then
         result := children
       end
     end
nex> function child_named(node: Map[String, Any], name: String): ?Map[String, Any]
     do
       result := nil
       across children_of(node) as child do
         if text_of(child, "name") = name then
           result := child
         end
       end
     end

text_of and cents_of work unchanged on nodes, because a node keeps its name under "name" and its amount under "cents", just as a record does.

Adding an expense to the tree means following its category path down from the root, one name at a time, and creating any node that does not exist yet. That is a recursive process (Chapter 8):

  • Base case: the path is empty. We have arrived at the right node, so add the amount to it.
  • Recursive case: find the child named by the first step of the path, creating it if necessary, and add the expense to that child using the rest of the path.
nex> function add_to_tree(node: Map[String, Any], path: Array[String], cents: Integer)
     do
       if path.is_empty then
         node.set("cents", cents_of(node) + cents)
       else
         let name := path.get(0)
         let rest := path.slice(1, path.length)
         if ? child_named(node, name) as child then
           add_to_tree(child, rest, cents)
         else
           let child := new_node(name)
           children_of(node).add(child)
           add_to_tree(child, rest, cents)
         end
       end
     end

Each recursive call is given a shorter path, so the recursion must reach the base case. Watch a small tree grow:

nex> let small := new_node("All")
{"name": "All", "cents": 0, "children": []}
nex> add_to_tree(small, ["Food", "Groceries"], 4250)
nex> small
{"name": "All", "cents": 0, "children": [{"name": "Food", "cents": 0, "children": [{"name": "Groceries", "cents": 4250, "children": []}]}]}
nex> add_to_tree(small, ["Food", "Dining out"], 3120)
nex> small
{"name": "All", "cents": 0, "children": [{"name": "Food", "cents": 0, "children": [{"name": "Groceries", "cents": 4250, "children": []}, {"name": "Dining out", "cents": 3120, "children": []}]}]}

The second call found the existing Food node and added Dining out beside Groceries. This only works because maps and arrays are shared, not copied. The node that children_of(node).add(child) puts into the tree is the very map that the next line passes to the recursive call, so the amount set in that call is set in the tree.

Building the tree for a list of expenses adds them one by one, each with its category path split at the slashes:

nex> function build_tree(expenses: Array[Map[String, Any]]): Map[String, Any]
     do
       result := new_node("All")
       across expenses as e do
         add_to_tree(result, text_of(e, "category").split("/"), cents_of(e))
       end
     end
nex> let tree := build_tree(november)

Walking the Tree

The total for a node is its own amount plus the totals of all its children, and each child's total is worked out the same way. The definition is recursive, so the function is too:

nex> function tree_total(node: Map[String, Any]): Integer
     do
       result := cents_of(node)
       across children_of(node) as child do
         result := result + tree_total(child)
       end
     end
nex> format_cents(tree_total(tree))
"341.75"

There is no separate base case to write. A node with no children is a leaf, and for a leaf the across loop runs zero times, so tree_total just returns the node's own amount.

Printing the whole report is a traversal: visit every node, print it, then print its children one level further in:

nex> function print_tree(node: Map[String, Any], indent: Integer)
     do
       let padding := ""
       repeat indent do
         padding := padding + "  "
       end
       console.print_line(padding + text_of(node, "name") + "  " + format_cents(tree_total(node)))
       across children_of(node) as child do
         print_tree(child, indent + 1)
       end
     end
nex> print_tree(tree, 0)
All  341.75
  Housing  204.30
    Utilities  84.30
    Repairs  120.00
      Plumbing  120.00
  Food  112.45
    Groceries  81.25
    Dining out  31.20
  Transport  25.00

Every line shows the total for everything underneath it: Food's 112.45 is Groceries plus Dining out. repeat (Section 5.6) builds the indentation, two spaces per level. Rent does not appear, because the rent was paid in October.

The shape of the code follows the shape of the data. A tree is a node with a list of smaller trees, so a function over a tree handles one node and then calls itself on each smaller tree. Once you have seen this pattern, you will recognise it in file systems, organisation charts, and the structure of programs themselves.

Searching the Tree

To answer "how much went on Food, and on what?", find the Food node and print just that part of the tree. Searching uses the same recursive shape. Check this node; if it is not the one, search each child in turn until one of them finds it:

nex> function find_node(node: Map[String, Any], name: String): ?Map[String, Any]
     do
       result := nil
       if text_of(node, "name") = name then
         result := node
       else
         across children_of(node) as child do
           if result = nil then
             result := find_node(child, name)
           end
         end
       end
     end
nex> if ? find_node(tree, "Food") as food then
       print_tree(food, 0)
     end
Food  112.45
  Groceries  81.25
  Dining out  31.20
nex> find_node(tree, "Travel") = nil
true

The return type is detachable, because a search can come back empty-handed. The test if result = nil stops the search once something has been found, so a later child cannot overwrite the answer.

Budgets

A budget sets a monthly limit for each top-level category. It is naturally a map from category to limit, in cents:

nex> let budgets: Map[String, Integer] := {"Food": 12000, "Housing": 100000, "Transport": 2000}
{"Food": 12000, "Housing": 100000, "Transport": 2000}

Comparing what was spent against a limit gives one of three answers. Choosing a value from a condition is what when is for (Section 4.4), and two of them nest to make three choices:

nex> function budget_status(spent, limit: Integer): String
     do
       let percent := spent * 100 / limit
       result := when percent > 100 then "OVER"
                 else when percent >= 90 then "close" else "ok" end end
     end
nex> budget_status(11245, 12000)
"close"

budget_status divides by limit, so it only works when limit is not zero. That is its precondition, in the language of Section 7.1. A budget of zero would make no sense anyway, and Part V shows how to write such a condition into the function so that Nex checks it.

The budget report puts together pieces we already have:

nex> function print_budgets(expenses: Array[Map[String, Any]], budgets: Map[String, Integer])
     do
       let spent := totals_by_category(expenses)
       across budgets.keys.sort as name do
         let used := spent.try_get(name, 0)
         let limit := budgets.get(name)
         console.print_line(name + ": " + format_cents(used) + " of " + format_cents(limit)
                            + "  " + budget_status(used, limit))
       end
     end
nex> print_budgets(november, budgets)
Food: 112.45 of 120.00  close
Housing: 204.30 of 1000.00  ok
Transport: 25.00 of 20.00  OVER

try_get(name, 0) matters here: a category with a budget but no spending this month has spent nothing, not caused an error.

The Complete Program

All that remains is a loop that reads commands and runs them. Here is the complete program. Save it as tracker.nex in the same folder as expenses.txt:

-- tracker.nex: an expense tracker that keeps its data in expenses.txt.
intern io/Path

-- Reading the log ---------------------------------------------------

function is_amount(text: String): Boolean
do
  result := text.length > 0
    and text.all(fn (c) => "0123456789.".contains(c.to_string))
    and text.count(fn (c) => c = #.) <= 1
end

function parse_line(line: String): ?Map[String, Any]
do
  result := nil
  let fields := line.split(",")
  if fields.length = 3 then
    let date := fields.get(0).trim
    let category := fields.get(1).trim
    let amount := fields.get(2).trim
    if date.length = 10 and category.length > 0 and is_amount(amount) then
      result := {"date": date, "category": category,
                 "cents": (amount.to_real * 100.0).round}
    end
  end
end

function load_expenses(file: Path): Array[Map[String, Any]]
do
  result := []
  if file.exists then
    across file.read_text.split("\n") as line do
      if ? parse_line(line) as expense then
        result.add(expense)
      end
    end
  end
end

-- Reading a record --------------------------------------------------

function text_of(record: Map[String, Any], key: String): String
do
  result := ""
  if convert record.get(key) to text: String then
    result := text
  end
end

function cents_of(record: Map[String, Any]): Integer
do
  result := 0
  if convert record.get("cents") to cents: Integer then
    result := cents
  end
end

function format_cents(cents: Integer): String
do
  let rest := cents % 100
  result := (cents / 100).to_string + "." + when rest < 10 then "0" else "" end + rest.to_string
end

-- Questions about the log -------------------------------------------

function in_month(expenses: Array[Map[String, Any]], month: String): Array[Map[String, Any]]
do
  result := expenses.filter(fn (e) => text_of(e, "date").starts_with(month))
end

function total(expenses: Array[Map[String, Any]]): Integer
do
  result := expenses.fold(0, fn (sum, e) => sum + cents_of(e))
end

function top_level(category: String): String
do
  result := category.split("/").get(0)
end

function by_month(expenses: Array[Map[String, Any]]): Map[String, Array[Map[String, Any]]]
do
  result := {}
  across expenses as e do
    let month := text_of(e, "date").substring(0, 7)
    let group := result.try_get(month, [])
    group.add(e)
    result.set(month, group)
  end
end

function totals_by_category(expenses: Array[Map[String, Any]]): Map[String, Integer]
do
  result := {}
  across expenses as e do
    let name := top_level(text_of(e, "category"))
    result.set(name, result.try_get(name, 0) + cents_of(e))
  end
end

-- The category tree ---------------------------------------------------

function new_node(name: String): Map[String, Any]
do
  result := {"name": name, "cents": 0, "children": []}
end

function children_of(node: Map[String, Any]): Array[Map[String, Any]]
do
  result := []
  if convert node.get("children") to children: Array[Map[String, Any]] then
    result := children
  end
end

function child_named(node: Map[String, Any], name: String): ?Map[String, Any]
do
  result := nil
  across children_of(node) as child do
    if text_of(child, "name") = name then
      result := child
    end
  end
end

function add_to_tree(node: Map[String, Any], path: Array[String], cents: Integer)
do
  if path.is_empty then
    node.set("cents", cents_of(node) + cents)
  else
    let name := path.get(0)
    let rest := path.slice(1, path.length)
    if ? child_named(node, name) as child then
      add_to_tree(child, rest, cents)
    else
      let child := new_node(name)
      children_of(node).add(child)
      add_to_tree(child, rest, cents)
    end
  end
end

function build_tree(expenses: Array[Map[String, Any]]): Map[String, Any]
do
  result := new_node("All")
  across expenses as e do
    add_to_tree(result, text_of(e, "category").split("/"), cents_of(e))
  end
end

function tree_total(node: Map[String, Any]): Integer
do
  result := cents_of(node)
  across children_of(node) as child do
    result := result + tree_total(child)
  end
end

function print_tree(node: Map[String, Any], indent: Integer)
do
  let padding := ""
  repeat indent do
    padding := padding + "  "
  end
  console.print_line(padding + text_of(node, "name") + "  " + format_cents(tree_total(node)))
  across children_of(node) as child do
    print_tree(child, indent + 1)
  end
end

function find_node(node: Map[String, Any], name: String): ?Map[String, Any]
do
  result := nil
  if text_of(node, "name") = name then
    result := node
  else
    across children_of(node) as child do
      if result = nil then
        result := find_node(child, name)
      end
    end
  end
end

-- Budgets -------------------------------------------------------------

function budget_status(spent, limit: Integer): String
do
  let percent := spent * 100 / limit
  result := when percent > 100 then "OVER"
            else when percent >= 90 then "close" else "ok" end end
end

function print_budgets(expenses: Array[Map[String, Any]], budgets: Map[String, Integer])
do
  let spent := totals_by_category(expenses)
  across budgets.keys.sort as name do
    let used := spent.try_get(name, 0)
    let limit := budgets.get(name)
    console.print_line(name + ": " + format_cents(used) + " of " + format_cents(limit)
                       + "  " + budget_status(used, limit))
  end
end

-- The program ---------------------------------------------------------

let file: Path := create Path.make("expenses.txt")
let budgets: Map[String, Integer] := {"Food": 12000, "Housing": 100000, "Transport": 2000}
let expenses := load_expenses(file)
console.print_line(expenses.length.to_string + " expenses loaded")

from
  let done := false
until
  done
do
  let command := console.read_line("> ").trim
  case command of
    "list" then
      across expenses as e do
        console.print_line(text_of(e, "date") + "  " + text_of(e, "category")
                           + "  " + format_cents(cents_of(e)))
      end
    "report" then print_tree(build_tree(expenses), 0)
    "months" then do
      let months := by_month(expenses)
      across months.keys as month do
        console.print_line(month + "  " + format_cents(total(months.get(month))))
      end
    end
    "category" then do
      let name := console.read_line("category: ").trim
      if ? find_node(build_tree(expenses), name) as node then
        print_tree(node, 0)
      else
        console.print_line("no category called " + name)
      end
    end
    "month" then do
      let month := console.read_line("month (YYYY-MM): ").trim
      print_tree(build_tree(in_month(expenses, month)), 0)
    end
    "budget" then do
      let month := console.read_line("month (YYYY-MM): ").trim
      print_budgets(in_month(expenses, month), budgets)
    end
    "add" then do
      let date := console.read_line("date (YYYY-MM-DD): ").trim
      let category := console.read_line("category: ").trim
      let amount := console.read_line("amount: ").trim
      let line := date + "," + category + "," + amount
      if ? parse_line(line) as expense then
        file.append_text(line + "\n")
        expenses.add(expense)
        console.print_line("saved")
      else
        console.print_line("not saved: expected a date, a category and an amount like 12.50")
      end
    end
    "quit" then done := true
    else console.print_line("commands: list, report, months, month, category, budget, add, quit")
  end
end

Most of the file is the functions from the previous sections, gathered under comments that say which part of the job each group does. No forward declarations are needed: in a program file, Nex reads all the function definitions before it runs anything (Section 6.6).

The new part is at the bottom. The program loads the log once, then runs a from ... until ... do loop (Chapter 5) until done becomes true. repeat would not do here, because we cannot know in advance how many commands will be typed. Each pass reads one command with console.read_line and hands it to a case (Section 4.5). A branch that needs more than one statement wraps them in do ... end, and the else branch answers anything it does not recognise with the list of commands.

Look at how add checks its input. It builds the line exactly as it will be written to the file, then runs it through parse_line, the same function that reads the file. A line is saved only if the tracker will be able to read it back. Using one function for both directions means the reading and the writing can never disagree about what a valid line is.

Here is a session. Run the program, record an expense, and quit:

$ nex tracker.nex
8 expenses loaded
> category
category: Food
Food  173.60
  Groceries  142.40
  Dining out  31.20
> add
date (YYYY-MM-DD): 2026-11-10
category: Transport
amount: 4.50
saved
> quit

Then run it again:

$ nex tracker.nex
9 expenses loaded
> months
2026-10  961.15
2026-11  346.25
> quit

The new expense survived the end of the program, because add wrote it to expenses.txt. This is the difference a file makes: the REPL forgets everything when you leave it, but the data in a file stays until something changes it. (The Food total here, 173.60, covers both months, because the category command searches the tree of all expenses, not just one month's.)

One thing in this program is less pleasant than the rest: all the Map[String, Any]. Every record and every node is a bag of values whose types Nex cannot see, and we needed convert each time we took one out. Nothing stops you from misspelling "cents" as "cent", either. cents_of would quietly return zero. Chapter 12 introduces classes, which let you describe an Expense with a date, a category and an amount of known types. With an Expense class, nearly all of these conversions disappear, and a misspelled field name is caught before the program runs.

One last word about across. Every loop in this chapter has run over a built-in collection. But across is not restricted to built-in types. It works with any object that can hand it a cursor: a small helper that visits the elements one at a time. That is how a type you write yourself becomes iterable with exactly the loop form you already know. We build such a type in Section 15.8, once classes and generics are in hand.

Summary

  • A program that has to remember things between runs keeps them in a file. Bring in Path with intern io/Path, and make one with create Path.make(name)
  • read_text reads a whole file as a string; write_text replaces a file's contents; append_text adds to the end; exists says whether the file is there
  • A log with one record per line is easy to append to and easy to read back: split("\n") into lines, then split(",") into fields
  • Parsing turns text into data. Check text before converting it, and return nil for a line that does not parse rather than stopping the program
  • Keep money in whole cents as an Integer. Real arithmetic cannot represent most decimal fractions exactly
  • An array of maps holds a sequence of records; a map of arrays groups records under a name. Build groups with the get-modify-set idiom
  • A map with values of different types must be a Map[String, Any], and its values come out as Any
  • if convert expr to name: Type then ... else ... end checks at run time that a value has the expected type, and gives it to you with that type if it does
  • Hide convert inside small accessor functions so that the rest of the program reads cleanly
  • A tree is a node holding a list of smaller trees. Functions over trees follow the same shape: handle one node, then recurse on each child
  • Validate input with the same function that reads the data back, so the two can never disagree
  • across is not limited to the built-in collections: any type that is Iterable, which means it can produce a cursor, works with the same loop form. We return to this in Section 15.8
