Chapter 29

A Spreadsheet: The Command Line

The formula language of Chapter 27 and the sheet of Chapter 28 are complete, but nobody can use them yet. This chapter adds the last layer: commands that a user types, a grid that shows the sheet, saving and loading, the main program, and the tests that hold it all together. It ends by looking back at what the project shows.

Commands as Data

A user types a line. Before the program can do anything with it, it has to know which command the line is, and what the command’s parts are. That is the same problem as reading a formula, on a smaller scale, and it has the same solution: turn the text into data first, and act on the data second.

union Command
  Assign(name: String, text: String)
  Show_All
  Show(name: String)
  Clear(name: String)
  Save(path: String)
  Load(path: String)
  Help
  Quit
  Unknown(text: String)
end

function parse_command(line: String): Command do
  let text := line.trim
  let words := text.split(" ").filter(fn (w: String): Boolean do result := w /= "" end)
  if text.contains("=") then
    let i := text.index_of("=")
    result := create Assign.make(text.substring(0, i).trim.to_upper,
                                 text.substring(i + 1, text.length).trim)
  elseif words.length = 1 and words.get(0) = "show" then
    result := create Show_All
  elseif words.length = 2 and words.get(0) = "show" then
    result := create Show.make(words.get(1).to_upper)
  elseif words.length = 2 and words.get(0) = "clear" then
    result := create Clear.make(words.get(1).to_upper)
  elseif words.length = 2 and words.get(0) = "save" then
    result := create Save.make(words.get(1))
  elseif words.length = 2 and words.get(0) = "load" then
    result := create Load.make(words.get(1))
  elseif words.length = 1 and words.get(0) = "help" then
    result := create Help
  elseif words.length = 1 and words.get(0) = "quit" then
    result := create Quit
  else
    result := create Unknown.make(text)
  end
end

Every line becomes a Command, including lines that are not commands at all: Unknown keeps the text so that the error message can repeat it. Assignment is recognised by its =, and the cell name is upper-cased here, at the edge of the program, so that everything inside sees names in one form.

Keeping parsing separate from running pays off twice. Each half can be tested on its own, and the code that runs a command never has to look at text again.

Asking Before Acting

Running a command is a match with one clause per command, each returning what to print, so that the main loop and the tests can share it:

-- Carry out `cmd`, returning what to print ("" for nothing).
function run(sheet: Sheet, cmd: Command): String do
  match cmd of
    Assign(name, text) then result := assign(sheet, name, text)
    Show_All           then result := format_grid(sheet)
    Show(name)         then result := show_cell(sheet, name)
    Clear(name)        then result := clear_cell(sheet, name)
    Save(path)         then result := save(sheet, path)
    Load(path)         then result := load(sheet, path)
    Help               then result := help_text()
    Quit               then result := ""
    Unknown(text)      then result := "Error: unknown command: " + text
  end
end

function assign(sheet: Sheet, name, text: String): String do
  result := ""
  if not is_cell_name(name) then
    result := "Error: " + name + " is not a cell name"
  else
    match parse_formula(text) of
      Err as e then result := "Error: " + e.error
      Ok as ok then
        if sheet.would_cycle(name, ok.value) then
          result := "Error: " + name + " = " + text + " would make " + name + " depend on itself"
        else
          sheet.set(name, ok.value)
        end
    end
  end
end

function show_cell(sheet: Sheet, name: String): String do
  if is_cell_name(name) then
    result := show_value(sheet.value_of(name))
    if sheet.has(name) then
      result := result + "   (" + name + " = " + sheet.text_of(name) + ")"
    end
  else
    result := "Error: " + name + " is not a cell name"
  end
end

function clear_cell(sheet: Sheet, name: String): String do
  result := ""
  if is_cell_name(name) then
    sheet.clear(name)
  else
    result := "Error: " + name + " is not a cell name"
  end
end

assign is where the user’s mistakes meet the sheet’s contracts, and it is worth reading slowly. Sheet.set has two preconditions: the name must be a cell name, and the formula must not create a cycle. A user can easily type something that breaks either. But a precondition violation means a bug in the program (Chapter 21), and a user typing Q100 = 1 has not found a bug. So assign checks every precondition itself, with the queries the sheet provides for exactly that purpose, and turns each failure into a message. It calls set only when set’s contract is sure to be met.

This is the division of labour that Design by Contract asks for. The sheet states its rules once and enforces them; the command layer, which knows that its input comes from a person, takes responsibility for meeting those rules or explaining why it cannot. If someone later adds a command and forgets a check, the precondition reports the mistake at the call that made it.

Showing the Grid

The grid shows every column and row up to the last one in use, with each value right-aligned in a column ten characters wide:

function pad_left(text: String, width: Integer): String do
  result := text
  from until result.length >= width do
    result := " " + result
  end
end

function trim_right(text: String): String do
  result := text
  from until result.length = 0 or result.char_at(result.length - 1) /= #space do
    result := result.substring(0, result.length - 1)
  end
end

function format_grid(sheet: Sheet): String do
  let width := 10
  let last_column := 0
  let last_row := 1
  across sheet.cells.keys as name do
    last_column := last_column.max(column_of(name))
    last_row := last_row.max(row_of(name))
  end
  result := "    "
  from let col := 0 until col > last_column do
    result := result + pad_left(column_letters().char_at(col).to_string, width)
    col := col + 1
  end
  from let row := 1 until row > last_row do
    let line := pad_left(row.to_string, 4)
    from let col := 0 until col > last_column do
      let name := cell_name(col, row)
      let shown := when sheet.has(name) then show_value(sheet.value_of(name)) else "" end
      line := line + pad_left(shown, width)
      col := col + 1
    end
    result := result + "\n" + trim_right(line)
    row := row + 1
  end
end

The display reads the sheet only through its public queries, has and value_of, and the layout lives entirely in this module. A different display, a web page or a window, would replace this function and leave the sheet alone.

Saving and Loading

A sheet is saved as the commands that would rebuild it, one cell per line, in name order. Loading reads the file back and runs each line as a command:

function save(sheet: Sheet, path: String): String do
  let lines := sheet.cells.keys.sort.map(fn (name: String): String do
    result := name + " = " + sheet.text_of(name)
  end)
  create Path.make(path).write_text(lines.fold("", fn (text, line: String): String do
    result := text + line + "\n"
  end))
  result := "Saved " + sheet.count.to_string + " cells to " + path
end

function load(sheet: Sheet, path: String): String do
  let file := create Path.make(path)
  if not file.exists then
    result := "Error: no file " + path
  else
    result := ""
    across file.read_text.split("\n") as line do
      if line.trim /= "" then
        let output := run(sheet, parse_command(line))
        if output /= "" then
          result := result + output + "\n"
        end
      end
    end
    result := result + "Loaded " + path
  end
end

A saved sheet is ordinary text:

A1 = 120
A2 = 80
A3 = A1 + A2 * 2
A5 = A1 / (A2 - 80)
B1 = sum(a1:a3)

Saving formulas rather than values is what lets a loaded sheet recalculate. And replaying commands means that loading needs no parser of its own: every line goes through parse_command and assign, with all their checks, exactly as if the user had typed it. A line that someone has edited into nonsense is reported, and the rest of the file still loads.

Two properties make replay safe. The order of the lines does not matter: a line may refer to a cell that only comes later in the file, and until that cell is loaded it reads as zero, which recalculation corrects when it arrives. And replay can never create a cycle that the saved sheet did not have: the saved formulas had none, and no subset of them can have one either. If a hand-edited file does contain a cycle, the formula that would close it is refused with the usual message, and loading carries on.

The Main Program

With everything else in place, the program itself is a short loop:

-- spreadsheet.nex: a spreadsheet on the command line.
intern sheet/Commands

function main() do
  let sheet := create Sheet.make
  console.print_line("Nex spreadsheet. Type help for the commands.")
  from let done := false until done do
    console.print("> ")
    let line := console.read_line
    if line = nil then
      done := true
    else
      let cmd := parse_command(line)
      match cmd of
        Quit then done := true
        _    then
          do
            let output := run(sheet, cmd)
            if output /= "" then
              console.print_line(output)
            end
          end
      end
    end
  end
end

main()

console.read_line returns nil at the end of input, so the program stops cleanly both when the user types quit and when its input runs out, as it does when commands are piped in from a file. All the work happens in run; the loop only reads, runs, and prints.

How the Files Fit Together

The project is laid out as Chapter 23 described, with the modules under lib/ so that intern finds them:

spreadsheet/
  spreadsheet.nex        the main program
  tests.nex              the tests
  lib/sheet/
    formula.nex          cell names, tokens, the lexer, the parser
    evaluate.nex         values, Cell_Source, evaluation
    sheet.nex            cells and the sheet
    commands.nex         commands, the grid, saving and loading

Each module interns only the one below it:

spreadsheet.nex  →  sheet/Commands  →  sheet/Sheet  →  sheet/Evaluate  →  sheet/Formula

The arrows all point one way, from the parts that deal with people to the parts that deal with ideas. formula.nex knows nothing about sheets; evaluate.nex knows only the Cell_Source abstraction it defines; sheet.nex knows nothing about commands or the console. Each layer can be understood, tested and changed by reading it and the layers below it, and none of them would have to change to put a different face on the program.

The Tests

tests.nex follows the style of Chapter 25: one function per part of the program, each a list of labelled assert statements, so that a failure names the case that broke. The formula tests use the Fixed_Cells fake from Section 27.8; the sheet tests go through run, the same path a user’s commands take:

function test_sheet() do
  let sheet := create Sheet.make
  assert set_before_use: run(sheet, parse_command("A3 = A1 + A2 * 2")) = ""
  run(sheet, parse_command("A1 = 120"))
  run(sheet, parse_command("A2 = 80"))
  assert recalculated: show_value(sheet.value_of("A3")) = "280.00"
  assert cycle_refused: run(sheet, parse_command("A1 = A3")) = "Error: A1 = A3 would make A1 depend on itself"
  assert cycle_left_no_trace: sheet.text_of("A1") = "120"
  run(sheet, parse_command("clear A2"))
  assert cleared: show_value(sheet.value_of("A3")) = "120.00"
  print("sheet tests passed")
end

function test_cycle_is_a_precondition() do
  let sheet := create Sheet.make
  let reached := false
  run(sheet, parse_command("A1 = B1"))
  sheet.set("B1", create Formula.make("A1", create Ref.make("A1")))
  reached := true
  raise "test failed: a cycle was accepted"
rescue
  if reached then
    raise "test failed: a cycle was accepted"
  else
    print("cycle precondition test passed")
  end
end

The second test checks the interface boundary rather than the behaviour: setting a cycle directly, without asking would_cycle first, must violate the precondition. If it ever stops doing so, the test fails. Running the whole file checks every part:

$ nex tests.nex
"cell name tests passed"
"parsing tests passed"
"evaluation tests passed"
"sheet tests passed"
"cycle precondition test passed"
"command tests passed"
"save and load tests passed"

The tests and the contracts do different jobs here. The contracts check that every cell agrees with its formula, after every change, on any sheet at all. The tests check particular cases that contracts cannot: that 1 + 2 * 3 really is 7, that an unclosed parenthesis gives the right message, and that a saved sheet loads back the same.

What the Project Shows

The spreadsheet is a few hundred lines long, and nearly every idea in this book has a place in it. Looking back over the three chapters, a handful of principles did most of the work.

Write the contract before the code. The sheet’s two invariants came first, and the rest of its interface followed from them: no_cycle needed would_cycle, which needed depends_on, and consistent needed a recalculation in dependency order. As with the calendar of Chapter 20, the contract designed the queries.

Let contracts carry the arguments that code depends on. The lexer’s moved_on is why reading a formula ends. The sheet’s acyclic is why the dependency order exists and the walk that finds it ends. cell_name’s round trip ties three functions to one another. Each would otherwise be a comment, or nothing at all.

Keep the bugs in the contracts and the mistakes in the data. A precondition violation always means the program is wrong. Everything a user can get wrong, a bad formula, a bad name, a cycle, a division by zero, is handled as an ordinary outcome: a Result from the parser, a message from the command layer, a Failed value in a cell.

Listen when a contract fails. When the invariant consistent failed in the middle of a recalculation, the fault was not in the invariant but in the design, which let the evaluator call back into a sheet that was halfway through changing. The fix, a narrow Cell_Values view, made the program better as well as correct.

Depend on abstractions, and keep them small. The evaluator depends on Cell_Source, one deferred routine, instead of on the sheet. That made it testable with a fake before the sheet existed, and it is what allowed the narrow view.

Choose the representation for the changes you expect. Formulas are a union with operations written as match, because the kinds of formula are fixed by the grammar while the operations keep growing. Commands are a union for the same reason.

Make dependencies point one way. The modules form a line, from the console down to formulas, and no module knows about the ones above it.

None of these is specific to spreadsheets. They are the same principles at work in any program of this size, and they matter more, not less, as programs grow.

Summary

  • Turn input into data first and act on the data second; a union of commands keeps parsing and running separate and testable
  • A layer that receives input from people should meet the preconditions of the layer below it, using the queries that layer provides, and report what it cannot meet
  • Saving the commands that rebuild a state, and replaying them to load it, reuses every check the program already has
  • Modules whose dependencies all point one way can each be understood with only the modules below them
  • Contracts check general properties on every run; tests check particular cases, messages and round trips that contracts cannot express
  • Write the contract first, let it carry the program’s arguments, and treat a failed contract as information about the design

Exercises

1. Add a cells command that lists every cell with its formula, one per line, in name order. Which existing function already produces almost exactly this?

2. Add an export FILE command that writes the values of the sheet as comma-separated text, one line per row. How do you write a Failed value?

3. Make each column of the grid as wide as the widest value it holds, plus two spaces, instead of a fixed ten characters.

4. Add an undo command that reverses the last change to the sheet. What must the program remember about a change, including a change that created a cell or cleared one? Write a postcondition for undoing a change, in terms of text_of.

5. Typing A1 = with nothing after the = reports an error. A real spreadsheet would treat it as clearing the cell. Which function should make that decision? Implement it, and add a test.

6. A saved file is edited by hand so that it holds A1 = B1 and B1 = A1. Trace what load does with it, line by line. Is the result what a user would want?

7.* Add copy A3 B3, which copies a formula from one cell to another and shifts its references by the same distance, so that A1 + A2 copied from A3 to B3 becomes B1 + B2. Which module should know how to shift a formula? What must the precondition say about references that would be shifted off the grid?
